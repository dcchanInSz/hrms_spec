# Research: 小企业人力资源管理系统

## 决策汇总

### 技术栈选型

| 类别 | 选择 | 替代方案 | 理由 |
|------|------|----------|------|
| 后端运行时 | Node.js 18+ | Python, Go | 前后端统一 JS 生态，开发效率高 |
| Web 框架 | Express 4.x | Fastify, NestJS | 中间件丰富，学习成本低 |
| 数据库 | SQLite 3 | PostgreSQL, MySQL | 轻量、零配置、单文件，适合小型部署 |
| 前端框架 | React 18 | Vue 3, Svelte | 组件化成熟，生态丰富 |
| UI 框架 | TailwindCSS | Material UI, Ant Design | 原子化 CSS，定制灵活，体积小 |
| 构建工具 | Vite 5 | Webpack, Create React App | 开发启动快，热更新优秀 |
| 认证 | JWT + bcrypt | Passport.js | 无状态、可扩展 |
| 测试 | Jest + RTL | Vitest, Cypress | 生态成熟，React 测试友好 |

## 详细分析

### 为什么选择 SQLite？

**优点**:
- 单文件存储，备份简单（cp 或复制文件）
- 无需独立数据库服务，降低运维成本
- 对于 10-50 用户，性能完全足够
- 支持完整 SQL 查询，灵活性高
- 内置事务支持，保证数据一致性

**缺点**:
- 不适合高并发写入场景
- 无原生网络协议，本地文件访问

**结论**: 对于 10-50 人企业，SQLite 的优点远大于缺点。

### 为什么选择 TailwindCSS？

**优点**:
- 原子化 CSS，类名即样式，避免样式冲突
- 响应式设计内置支持（sm:, md:, lg: 等）
- 按需生成 CSS，体积小
- 设计系统友好（可配置主题色、间距等）

**与组件库对比**:
- Ant Design/MUI: 组件丰富但体积大，定制成本高
- TailwindCSS: 更灵活，组件需自行构建但可控

**结论**: 符合用户体验一致性要求，团队可建立统一设计 token。

### 为什么选择 JWT 认证？

**优点**:
- 无状态，服务端无需存储 session
- 适合前后端分离架构
- 可包含用户角色信息，减少额外查询
- 过期机制支持自动登出

**安全考虑**:
- Token 存储于 localStorage（XSS 风险）或 httpOnly cookie
- 实现刷新令牌机制
- 设置合理的过期时间（建议 24 小时）

## 替代方案评估

### 后端框架：Fastify

- 性能更高（声称 2x Express）
- Schema 验证更完善
- 但生态不如 Express 成熟

**选择 Express**: 团队熟悉度优先，性能在小规模场景非关键

### 数据库：PostgreSQL

- 功能更强大（JSON 支持、全文搜索）
- 适合大规模数据
- 但需要独立服务部署

**选择 SQLite**: 运维简化优先，10-50 用户无需分布式

## 结论

本技术栈平衡了：
1. **开发效率**: 前后端统一语言，丰富的 npm 包
2. **运维简单**: SQLite 单文件，零配置运行
3. **用户体验**: React + TailwindCSS 保证界面质量和一致性
4. **代码质量**: Jest 测试框架支持 TDD
5. **性能达标**: 轻量架构满足 10-50 并发用户
